# 性能测试（2026-11-18）

环境：Windows 11 + Docker Desktop（WSL2），笔记本 CPU；系统使用 TF-IDF v2 中英混合模型（校准后）+ 28 条规则。

## 检测引擎

在 api 容器内直接调用检测引擎，对 1000 封中英文测试邮件（含邮件头、链接，正文长度 1–20 倍随机）逐封检测（解析 + 规则 + 模型 + 融合）：

| 指标 | 耗时 |
|---|---|
| 平均 | 2.90 ms |
| P50 | 2.79 ms |
| P95 | 3.96 ms |
| P99 | 4.89 ms |
| 最大 | 6.32 ms |

需求要求单封 P95 ≤ 300 ms，满足。

## 接口（经 Nginx 反向代理到 FastAPI，含 JWT 校验与数据库查询）

| 接口 | 请求次数 | P50 | P95 |
|---|---|---|---|
| 手动检测 POST /api/v1/detect/text | 200 | 12.0 ms | 34.1 ms |
| 邮件列表 GET /api/v1/emails | 100 | 14.6 ms | 37.6 ms |
| 总览统计 GET /api/v1/stats/overview | 100 | 20.3 ms | 41.2 ms |

## 邮箱同步

真实 QQ 邮箱接入时回扫 50 封邮件：拉取 + 检测 + 入库共 16.5 秒（约 0.33 秒/封，主要耗时在 IMAP 网络往返）。需求要求 50 封不超过 30 秒，满足。

## 测试中发现并修复的问题

- api 容器重建后 IP 变化，Nginx 只在启动时解析一次 `api` 主机名，导致前端请求返回 502。改为通过 Docker 内置 DNS（127.0.0.11）动态解析后，单独重启 api 不再影响前端。
