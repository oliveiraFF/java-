# 实验记录

## 2026-11-13 · 实验 1：TF-IDF 基线

- 数据：Kaggle Phishing Email Dataset 六个子集，清洗去重后 81,879 封（原始 82,486，重复 596，过短 11）；按来源 × 标签分层划分 70/10/20，先去重后划分。
- 脚本：`ml/scripts/prepare_data.py`、`ml/scripts/train_baseline.py`
- 完整结果：`ml/reports/baseline.md`、`ml/reports/baseline_metrics.json`

### 结果摘要

| 模型 | 全量 F1 | 钓鱼专项 F1 | 钓鱼专项精确率 | FPR≤1% 时召回 | 推理(ms/封) |
|---|---|---|---|---|---|
| 朴素贝叶斯 | 0.9778 | 0.9691 | 0.9671 | 0.9778 | 0.005 |
| 逻辑回归 | 0.9923 | 0.9612 | 0.9280 | 0.9892 | 0.002 |
| 线性 SVM | **0.9933** | 0.9675 | 0.9388 | **0.9940** | 0.002 |
| 随机森林 | 0.9793 | 0.9146 | 0.8547 | 0.9465 | 0.169 |

### 观察

1. **全量指标接近满分，但不能直接当作"钓鱼检测能力"。** 换成钓鱼专项子集（钓鱼 + 诈骗 vs 正常）后，四个模型的精确率都明显下降（线性 SVM 0.9926 → 0.9388，随机森林 0.9809 → 0.8547）。原因是专项子集里正样本只有约 970 封，同样数量的误报在小正样本集上对精确率影响更大。论文中应同时报告两种口径。

2. **模型学到了"数据集来源捷径"（shortcut learning）。** 线性模型权重最大的词里大量是与钓鱼无关的来源痕迹：
   - 偏向正常：`enron`、`vince`、`louise`、`713`（休斯敦区号）、`python org`、`opensuse`、`edu` —— 这些是 Enron 公司内部邮件、Python/openSUSE 邮件列表的特征；
   - 偏向恶意：`2004`、`2005`、`crime 2008`、`video partners` —— 是特定年份、CNN 订阅邮件模板的痕迹。

   也就是说，模型很大程度上在判断"这封邮件来自哪个语料库"，而不是"这封邮件是否在诱导用户"。换成真实企业邮箱（没有 enron、python-dev 这些词）时，效果会大幅下降。

3. **这正好是本课题的研究动机。** 基于词频的模型依赖表层词汇，容易学到捷径；基于语义表征的模型理论上更关注语义意图。后续实验应专门验证这一点。

## 2026-11-15 · 实验 2：TF-IDF 基线的跨来源泛化

- 脚本：`ml/scripts/exp_generalization.py`；完整结果：`ml/reports/generalization.md`

### A. 留一来源（训练时完全不见某个来源，在该来源全部邮件上测试）

| 留出来源 | 线性 SVM 标准划分 F1 | 留一来源 F1 | 留一来源误报率 |
|---|---|---|---|
| CEAS | 0.9961 | 0.9313 | 10.7% |
| Enron | 0.9896 | **0.8453** | **21.9%** |
| SpamAssassin | 0.9795 | 0.8690 | 11.4% |
| Ling | 0.9670 | 0.8803 | 3.1% |

结论：一旦遇到没见过的邮件来源，F1 下降 6–14 个百分点，误报率普遍超过 10%，远达不到开发文档中"误报率 ≤ 1%"的上线要求。标准划分下 0.99 的成绩很大程度上来自"见过同类语料"。

### B. 屏蔽来源捷径词

做法：在训练集的**正常邮件**上用卡方检验，找出最能区分语料来源的 1000 个词，作为停用词后重新训练。

- 第一版在全部邮件上计算卡方，选出的却是 `fund`、`bank`、`transfer`、`urgent`、`beneficiary` 等真正的诈骗语义词：Nigerian、Nazario 两个来源全部是恶意邮件，"来源"与"标签"混在一起。改为只在正常邮件上计算后，选出的才是纯粹的语料痕迹：`enron`、`vince`、`hou`、`ect`、`python`、`mailman`、`listinfo`、语言学术语（Ling 邮件列表）、年份等。这一设计细节值得写进论文的方法部分。
- 结果（线性 SVM）：标准划分 F1 仅从 0.9933 降到 0.9899，说明模型并不只靠这些词；留一来源下 Enron 从 0.845 升到 0.878、SpamAssassin 从 0.869 升到 0.916，CEAS 和 Ling 略降（Ling 的语言学词汇既是来源痕迹也是它的正常话题，屏蔽后反而丢失了正常邮件的特征）。朴素贝叶斯在所有留一设定下都变差。

### 结论

1. 词频模型的高分有相当部分来自语料来源捷径，换到新环境误报率会大幅上升。
2. 人工屏蔽捷径词只能部分缓解（最多提升约 4 个百分点），且会误伤正常话题词，不是根本办法。
3. 下一步用 DistilBERT 语义表征模型做同样的留一来源实验，检验语义模型是否泛化得更好，这是论文的核心对比。

## 2026-11-15 · 实验 3：DistilBERT 语义表征模型

- 模型：`distilbert-base-multilingual-cased`，输入主题 + 正文前 256 token，2 个 epoch，batch 16，学习率 3e-5，fp16，RTX 4050 Laptop（6 GB）
- 脚本：`ml/scripts/train_distilbert.py`；汇总：`ml/scripts/compare_models.py` → `ml/reports/comparison.md`
- 全量训练耗时 26.4 分钟，GPU 推理 2.4 ms/封

### A. 标准划分：DistilBERT 全面领先，优势主要在降低误报

| 指标 | 线性 SVM（最佳基线） | DistilBERT |
|---|---|---|
| 全量 F1 | 0.9933 | 0.9939 |
| 误报率 | 0.80% | 0.41% |
| 钓鱼专项 F1 | 0.9675 | 0.9786 |
| 钓鱼专项精确率 | 0.9388 | 0.9677 |
| FPR≤1% 时召回 | 0.9940 | 0.9960 |

### B. 留一来源：DistilBERT 没有比基线泛化得更好（与预期相反）

| 留出来源 | 线性 SVM F1 / 误报率 | DistilBERT F1 / 误报率 |
|---|---|---|
| CEAS | 0.931 / 10.7% | 0.853 / 11.3% |
| Enron | 0.845 / 21.9% | 0.819 / 27.5% |
| SpamAssassin | 0.869 / 11.4% | 0.809 / 5.3% |
| Ling | 0.880 / 3.1% | 0.834 / 5.5% |
| **平均** | **0.882 / 11.8%** | **0.829 / 12.4%** |

每次留一训练的验证集 F1 都在 0.993 以上，换到未见过的来源后降到 0.82–0.85。

### 分析

1. **深度模型同样会学到捷径。** 语义模型并不会自动摆脱"来源风格"的捷径，这与 Geirhos 等人关于深度网络捷径学习（shortcut learning）的结论一致。论文的核心论点不能写成"语义模型泛化更好"，需要修正。
2. **留一来源测的主要是垃圾邮件识别，不是钓鱼识别。** CEAS、Enron、SpamAssassin、Ling 的正样本几乎全是广告推销类垃圾邮件，而且各语料对"垃圾邮件"的定义不同（Enron-Spam 的营销邮件在别的语料里可能算正常）。语义模型擅长的"诱导意图"在这个设定里体现不出来。
3. **排序能力还在，阈值不适配。** 跨来源 ROC-AUC 仍有 0.92–0.98，说明模型对"哪封更可疑"的排序大体正确，问题在于 0.5 这个阈值不适合新环境。这支持产品设计中"新接入邮箱先观察几天、在本地数据上校准阈值"的做法。
4. **多语言 cased 模型对英文略弱**，且只看前 256 token，也可能是因素之一（可作为消融项：换 `distilbert-base-uncased` 对比）。

### 调整后的研究路线

- **实验 4 · 未见钓鱼识别（最贴合题目）**：训练时去掉全部真实钓鱼邮件（Nazario），测试模型能否识别从未见过的钓鱼邮件，基线与 DistilBERT 对比召回率，误报率在正常邮件上统计。
- **实验 5 · 融合模型**：规则层（仿冒域名、链接、索取凭证等）不依赖语料来源，与模型融合后检验跨来源误报率能否下降。
- **实验 6 · 大模型改写鲁棒性**：原计划不变。
- **论文论点修正为**：单一模型（无论词频还是语义）都会受语料捷径影响；语义表征在同分布下误报更低，结合与来源无关的结构化规则可以提升跨环境的稳定性。

## 2026-11-15 · 实验 4：未见恶意类型识别与规则融合

- 设定：训练时完全去掉一类真实恶意邮件（Nazario 钓鱼 1,552 封 / Nigerian 诈骗 3,291 封），测试集 = 该类全部邮件 + 标准测试集正常邮件 7,850 封。
- 公平比较：每种方法都在验证集（同样不含该类）上选阈值使误报率 ≤ 1%，再在测试集上评估。
- 脚本：`ml/scripts/exp_unseen.py`、`train_distilbert.py --unseen`、`predict_distilbert.py`；完整结果：`ml/reports/unseen.md`

### 结果（未见钓鱼，Nazario）

| 方法 | 召回率 | 误报率 | ROC-AUC |
|---|---|---|---|
| 仅规则 | 0.207 | 0.79% | 0.690 |
| 线性 SVM | 0.620 | 0.75% | 0.982 |
| **规则 + 线性 SVM** | **0.666** | 0.76% | 0.983 |
| DistilBERT | 0.648 | 1.03% | **0.984** |
| 规则 + DistilBERT | 0.612 | 1.03% | 0.971 |
| 规则 + DistilBERT（Platt 校准后） | 0.619 | 0.89% | 0.972 |

未见诈骗（Nigerian）：所有模型召回率 0.976–0.995，融合与否差别在 0.3 个百分点以内。

### 结论

1. **未见过的钓鱼邮件是真正的难点。** 训练时没有钓鱼样本，所有模型在 1% 误报率下只能识别 53%–67%；诈骗邮件与垃圾邮件写法相近，即使没见过也能识别 99%。
2. **DistilBERT 是最好的单一模型**（召回 0.648、AUC 0.984 均最高），但领先线性 SVM 的幅度很小，且误报略高。
3. **规则融合对词频模型有效，对 DistilBERT 无效。** 规则 + 线性 SVM 召回提升 4.6 个百分点，是全场最好；规则 + DistilBERT 反而下降。合理的解释是：公开数据集只有正文，能触发的主要是"紧迫感、索取凭证"这类正文规则，而 DistilBERT 已经从语义中学到了这些信号，规则带来的只有重复信息和它自身的误报；词频模型缺少这类语义归纳，规则是互补信息。
4. **局限：** 公开数据集没有邮件头、HTML 和附件，认证、链接显示文本、附件等最具区分度的结构化规则在这里全部无法触发（见 `rules.md`）。真实邮件中融合的收益需要在系统上线后用真实邮件验证。

### 过程中修正的三个问题（论文方法部分可写）

1. **融合公式**：加权平均会给模型判断打折扣（规则未命中时模型 70% 的把握只得 42 分），改为 noisy-OR。
2. **分数取整**：DistilBERT 概率高度饱和，融合分先取整到 0–100 会丢失正常邮件之间的排序（AUC 从 0.984 跌到 0.886）；实验改用连续值，系统只在最终展示时取整。
3. **概率校准**：尝试 Platt 校准，对 DistilBERT 融合有小幅改善（误报 1.03% → 0.89%），但仍不如单独使用。调优到此为止，避免针对测试集反复调参。

### 对系统的决定

- 检测引擎采用"规则 + 模型"融合架构不变：规则提供与语料无关、用户看得懂的判定依据，在真实邮件的邮件头/链接/附件上才是主要价值所在。
- 模型选择留待系统联调时用真实邮件比较；当前证据下 DistilBERT 标准误报最低（0.41%），线性 SVM 推理快 1000 倍且与规则互补更好。

## 2026-11-16 · 实验 5：真实邮箱评估与标签重定义

- 数据：作者本人 QQ 邮箱最近 50 封邮件（观察模式，只检测不处置；数据只保存在本地，报告只记录统计数字）。经人工核对发件域名与主题，50 封**全部是正常邮件**：35 封中文、15 封英文，类型为招聘推荐、代码平台通知、账号安全验证码、营销广告、订单通知。
- 脚本：`ml/scripts/eval_real.py`；结果：`ml/reports/real_mailbox.md`；重新检测命令：`python -m app.rescan`

### A. 原始标签训练的模型在真实邮箱上几乎不可用

| 模型 | 被系统判为可疑及以上 | 被判为钓鱼 |
|---|---|---|
| TF-IDF 线性 SVM（恶意 vs 正常） | 34/50 | 13/50 |
| DistilBERT（恶意 vs 正常） | 25/50 | 25/50 |

规则层表现正常：有认证记录的发件人 DMARC 全部通过，邮件头和仿冒域名类规则没有误报。误报几乎全部来自模型。

**原因：** 公开数据集的标签 1 绝大多数是广告类垃圾邮件，模型实际学到的是"像不像广告"。现代的营销、招聘、通知邮件在模型看来就是垃圾邮件。

### B. 改为"钓鱼 vs 非钓鱼"重新训练

正样本只保留钓鱼（Nazario）与诈骗（Nigerian）邮件，垃圾/营销邮件归入负样本；使用类别权重处理不平衡（正样本约 6%）。

| 模型 | 公开测试集：钓鱼召回 | 诈骗召回 | 垃圾/营销误报 | 正常误报 | 真实邮箱：系统判可疑及以上 |
|---|---|---|---|---|---|
| TF-IDF 线性 SVM（钓鱼 vs 非钓鱼） | 0.965 | 0.983 | 2.0% | 0.04% | **5/50** |
| DistilBERT（钓鱼 vs 非钓鱼） | 0.981 | 0.986 | **0.2%** | 0.04% | 23/50 |

标签重定义后，TF-IDF 模型在真实邮箱上的误报从 34 封降到 5 封（其余 4 封误报来自正文话术规则和一条品牌域名名单缺失，已补充微软的官方域名）。

### C. 按语言拆分：两种模型都不能处理中文

另外人工构造了 5 封中文钓鱼邮件（冒充银行冻结账户、冒充领导要求转账、虚假退税、邮箱过期、虚假工资补贴；均为虚构样本）。

| 模型 | 真实中文邮件误报 | 真实英文邮件误报 | 构造的中文钓鱼识别 |
|---|---|---|---|
| TF-IDF（钓鱼 vs 非钓鱼） | 0/35 | 1/16 | **0/5**（分数 0.13–0.31） |
| DistilBERT（钓鱼 vs 非钓鱼） | 19/35 | 4/16 | **5/5**（分数 0.85–1.00） |

- TF-IDF 的训练词表全部是英文，对中文邮件几乎提取不到特征，分数一律很低：**真实中文邮件零误报是因为"看不懂"，同样也识别不出任何中文钓鱼**。实验 B 中它在真实邮箱上的好成绩主要来自这一点，不能当作真正的检测能力。
- DistilBERT 多语言模型能理解中文语义（构造的中文钓鱼全部识别），但训练时没见过正常的中文邮件，把大量中文通知、招聘邮件也判为可疑。

### 结论

1. **标签定义比模型结构更重要。** 把"垃圾邮件"当作正样本训练出的模型会把正常的营销和通知邮件大量误判；改为"钓鱼 vs 非钓鱼"后，公开数据和真实邮箱上的误报都明显下降。论文中应把这一点作为方法上的核心设计。
2. **只用英文数据训练无法支撑中文邮箱的检测**：词频模型对中文"失明"，语义模型对中文"过敏"。构建中文训练数据（中文正常邮件 + 中文钓鱼邮件）是必要的，这为开题时计划的"中文数据集构建"提供了直接的实验依据。
3. 公开测试集上的高分（F1 0.98–0.99）不能说明真实可用性，**真实环境评估必须作为论文的独立实验**。
4. 观察模式的设计得到验证：50 封真实邮件中出现了 36 封误报，但没有任何一封被移动。

### 下一步

- 构建中文数据：中文正常邮件（TREC06C 中的正常邮件 + 经同意的真实邮件，只在本地使用）；中文钓鱼邮件（公开的钓鱼预警样本 + 合成样本），再训练中英文混合的 DistilBERT。
- 系统暂时使用 TF-IDF（钓鱼 vs 非钓鱼）模型，误报最低；在中文能力补上之前，中文钓鱼主要依靠规则层识别。

## 2026-11-17 · 实验 6：加入中文数据的中英文混合训练

### 数据

| 来源 | 数量 | 说明 |
|---|---|---|
| 英文公开数据（实验 1） | 81,879 | 正常、垃圾、钓鱼、诈骗 |
| TREC06C 中文语料 | 25,151 | 正常 13,728 / 垃圾 11,423；原始 64,620 封，去重删除 30,920 封（群发广告的大量重复），乱码删除 95 封 |
| 中文钓鱼模板合成 | 2,000 | 12 类场景，虚构，`ml/scripts/synth_zh_phish.py` |
| **合计** | **109,030** | 目标"钓鱼 vs 非钓鱼"，正样本占 6.3% |

- TF-IDF 改用中英混合切分（英文按词，中文按单字和相邻两字，`phishguard_detector.text.tokenize_mixed`）。
- 评估集（均不参与训练）：手写中文测试集 40 封（`ml/testsets/zh_handwritten.csv`，钓鱼 20 封含 4 类模板外场景，正常 20 封覆盖验证码、账单、物流、安全提醒等现代通知类邮件）；作者真实 QQ 邮箱 51 封（全部正常）。

### 结果

| 模型 | 手写中文钓鱼召回 | 手写中文正常误报 | TREC06C 正常 / 广告误报 | 真实邮箱：系统判可疑及以上 |
|---|---|---|---|---|
| TF-IDF（英文） | 0/20 | 0/20 | 0% / 0% | 4/51 |
| TF-IDF（中英混合） | **14/20** | 3/20 | 0% / 0% | 7/51 |
| DistilBERT（英文） | 10/20 | 12/20 | 7.5% / 19.0% | 23/51 |
| DistilBERT（中英混合） | **18/20** | 9/20 | 0% / 0% | 10/51 |

- TF-IDF 混合版漏掉 6 封：冒充老师、刷单返利、冒充公检法、虚假会议（模板中没有的场景），以及快递理赔、密码重置（模板中有，但写法不同）；误报 3 封：账单、快递签收、安全提醒。
- DistilBERT 混合版漏掉 2 封，但把 9 封正常的现代通知类邮件判为钓鱼。

### 分析

1. **中文数据效果明显。** TF-IDF 的中文钓鱼识别从 0 到 14/20，DistilBERT 从"随机猜测"（召回 50%、误报 60%）提升到召回 90%；DistilBERT 在真实邮箱上的误报从 23 封降到 10 封。
2. **语义模型对新场景泛化更好。** 在模板中没有的诈骗场景上，DistilBERT 明显强于 TF-IDF，后者只能识别训练时见过的说法。这是本课题"语义表征"论点在中文上的直接证据。
3. **新的瓶颈是"现代通知类正常邮件"。** 两个模型在 TREC06C 正常邮件上误报都是 0，但在手写测试集的验证码、账单、安全提醒等邮件上误报较多（TF-IDF 3/20，DistilBERT 9/20）。原因是 TREC06C 采集于 2005 年，正常邮件以论坛讨论、私人通信为主，几乎没有现代平台发出的交易与安全通知；而这类邮件和钓鱼邮件在措辞上最像（账户、验证、异常、金额）。补充此类正常邮件是下一步的关键。
4. **模板合成的局限。** 模板钓鱼让模型学到了固定场景的说法，对模板外的新骗术识别不足；论文中应如实说明，并以手写测试集而不是模板测试划分作为评估依据。

### 对系统的决定

- 系统改用 TF-IDF 中英混合模型（`baseline_tfidf_phish_mixed.joblib`）：真实邮箱误报最低的同时具备基本的中文识别能力，CPU 推理不到 0.01 毫秒/封。
- DistilBERT 中英混合版识别能力最强，但误报更高、需要 GPU 才能保持低延迟，暂作论文对比；后续可导出 ONNX 并与规则融合后接入系统。

## 2026-11-18 · 实验 7：补充现代通知类正常邮件与阈值校准

- 动机：实验 6 发现 TREC06C（2005 年）缺少现代平台的验证码、登录提醒、账单、物流等通知类正常邮件，这类邮件是主要误报来源。
- 数据：模板合成 3,000 封通知类正常邮件（`ml/scripts/synth_notice_ham.py`：验证码、登录提醒、账单、物流、订单、会员、工资条、会议、校园、营销、英文平台通知），写法遵循真实平台：链接指向官方域名或不带链接、提醒勿泄露验证码、"如非本人操作请在 APP 内修改密码"。与实验 6 数据合并为 112,030 封（`emails_mixed2.csv`）。
- 局限：手写测试集中的正常邮件与通知模板均由作者编写，手写集上的误报数可能偏乐观；**真实邮箱评估不受影响**，作为主要依据。

### A. 固定阈值 0.5 下看似"召回下降"，实际是阈值问题

| 模型 | 手写集 AUC | 钓鱼分数中位数 | 高于正常邮件最高分的钓鱼 |
|---|---|---|---|
| TF-IDF v1 → v2 | 0.887 → **0.965** | 0.651 → 0.611 | 9/20 → **18/20** |
| DistilBERT v1 → v2 | 0.844 → **0.955** | 1.000 → 0.000 | 4/20 → **15/20** |

加入通知类正常邮件后两个模型的区分能力都提高了，但整体打分下降（DistilBERT v2 输出高度饱和，钓鱼分数中位数也接近 0），固定阈值 0.5 会截掉大部分钓鱼。

### B. 在验证集上选阈值（误报率 ≤ 1%）后评估

阈值只在验证集上选，测试集只用于评估。

| 模型 | 手写中文钓鱼召回 | 手写中文正常误报 | 真实邮箱（54 封）系统判可疑及以上 | 判钓鱼（会被隔离） |
|---|---|---|---|---|
| TF-IDF v1 | 18/20 | 6/20 | 20/54 | 1/54 |
| **TF-IDF v2** | **18/20** | **1/20** | **6/54** | **0/54** |
| DistilBERT v1 | 18/20 | 9/20 | 14/54 | 11/54 |
| DistilBERT v2 | 11/20 | 0/20 | 7/54 | 1/54 |

### C. 系统调整

- 系统改用 TF-IDF v2（`baseline_tfidf_phish_mixed2.joblib`），并启用阈值校准：把验证集阈值单调地映射到 0.5（分段线性，不改变邮件之间的排序），融合公式与 50 / 80 判定线保持不变。实现见 `phishguard_detector.engine.BaselineModel(calibrated=True)`。
- 用新模型重新检测真实邮箱最近 60 封（全部正常）：**判钓鱼 0 封、可疑 6 封、安全 54 封**。剩余 6 封误报都有规则命中（GitLab 邮箱确认、Steam 登录提醒触发"紧迫感"规则、阿里云激活链接为 http、订单通知站点使用小众顶级域名），误报来源已从模型转向规则层。

### 结论

1. 补充"现代通知类正常邮件"有效：TF-IDF 在召回不变的情况下，手写集误报从 6/20 降到 1/20，真实邮箱误报从 20 封降到 6 封，且不再有邮件会被误隔离。
2. **阈值必须随训练数据重新确定。** 正负样本构成变化后，模型分数的刻度会整体漂移；用固定 0.5 会得出"模型变差"的错误结论。论文中应强调阈值在验证集上选择、测试集只用于评估。
3. 在当前数据条件下，TF-IDF v2 是检测效果与误报的最佳平衡；DistilBERT 的优势体现在模板外新骗术的识别上（实验 6），但对数据分布变化更敏感、输出更饱和。
4. 下一步可优化规则层：对 DMARC 通过且非仿冒域名的发件人，降低正文话术类规则的权重。

### 实验 1–7 主线小结（论文实验章节可按此组织）

| 实验 | 问题 | 结论 |
|---|---|---|
| 1 | 基线能做到多好 | 公开数据集上 F1 0.99，但依赖语料来源捷径词 |
| 2 | 换一个来源还行吗 | 留一来源 F1 降 6–14 个点，误报率超过 10% |
| 3 | 语义模型更好吗 | 同分布下误报减半，跨来源并不更好 |
| 4 | 没见过的钓鱼能识别吗 | 最好的方法也只识别 2/3；规则融合对词频模型有效 |
| 5 | 真实邮箱表现如何 | 原始标签模型误报 68%；标签改为"钓鱼 vs 非钓鱼"后大幅下降，但英文模型无法处理中文 |
| 6 | 加入中文数据 | 中文钓鱼识别从 0 到 70%–90%；语义模型对新骗术泛化更好 |
| 7 | 补充现代通知邮件 + 阈值校准 | 真实邮箱误报 6/60、零误隔离，系统采用 TF-IDF v2 |

## 2026-11-18 · 实验 8：认证可信发件人的规则降权

- 动机：实验 7 中真实邮箱剩余的 6 封误报都有正文话术或链接规则命中（GitLab 邮箱确认、Steam 登录提醒、阿里云激活链接等），且这些邮件都通过了 DMARC 认证。
- 做法（`phishguard_detector/rules.py`）：
  1. **发件人可信**：DMARC 通过（From 中的域名确实发出了这封邮件），且没有命中任何冒充类规则（发件域名仿冒、显示名冒充品牌、显示名伪装邮箱、回复地址不一致、免费邮箱冒充领导）。此时"紧迫感、索取账号、金钱、账户威胁"四条正文话术规则权重减半，并在检测依据中注明原因。
  2. **指向自家域名的链接**：认证通过时，链接指向发件人自己的域名，不触发"登录页未加密、高风险顶级域名、子域名层级过多"。
  3. 攻击者自己注册的仿冒域名（如 paypa1.com）也能配置 DMARC，因此仿冒域名一律不算可信。
- 公开数据集没有认证结果，实验 1–7 的结论不受影响；单元测试覆盖了上述各种情况（23 个检测引擎测试、17 个后端测试全部通过）。

### 结果（真实邮箱最近 60 封，全部正常）

| 邮件 | 规则分 前 → 后 | 模型分（校准后） | 风险分 前 → 后 |
|---|---|---|---|
| GitLab 邮箱确认 | 25 → 13 | 0.63 | 71 → 67 |
| 阿里云激活通知 | 10 → 0 | 0.57 | 60 → 57 |
| Steam 登录提醒 ×3 | 10 → 5 | 0.49–0.51 | 53–56 → 51–54 |
| 订单发货通知 | 10 → 10（链接指向其他域名，不豁免） | 0.50 | 54 → 54 |

系统判定仍为可疑 6 封、钓鱼 0 封。

### 结论

1. 规则层的误报贡献降低了 50%–100%，但判定没有改变：**剩余 6 封误报的模型分都落在阈值附近（0.49–0.63），已经是模型的边界样本，而不是规则问题。**
2. 没有把"认证可信"进一步用于压低模型分：那等于"真实域名发来的都可信"，会让被盗企业邮箱发出的钓鱼几乎无法识别。这是有意的取舍。
3. 对固定的、可信的通知发件方（如游戏平台、代码托管平台），更合适的做法是由管理员加入白名单（命中白名单且认证通过时风险分 -20），系统已支持。
4. 检测依据中会注明"发件人已通过 DMARC 身份认证，此项权重减半"，保证判定过程对用户透明。

## 2026-11-18 · 实验 9：大语言模型改写的鲁棒性（任务书补充项）

- 动机：大语言模型让攻击者可以批量生成语句通顺的钓鱼邮件，过去"语句生硬、拼写错误"的线索失效。检验模型对"同样内容、换一种自然写法"是否稳健。
- 改写方法（`ml/scripts/llm_rewrite.py`）：DeepSeek（deepseek-chat，温度 0.8），提示词要求"把邮件改写成语气自然、像真人写的版本，保持原意、请求和链接不变"。**提示词是中性的润色，没有要求规避检测**，因此本实验衡量的是写法变化下的稳健性，不是对抗攻击下的下限。
- 只把公开数据和合成数据发给外部接口，真实邮箱邮件不参与。
- 改写对象：
  - 测试：英文测试集钓鱼 200、正常 100；手写中文钓鱼 20、正常 20（各有 1 封被模型拒绝改写，实际 199+99+19+20）。
  - 增强训练：英文训练集钓鱼 300、中文模板钓鱼 200、正常 300（只来自训练划分，与测试样本不重叠）。
  - 共消耗约 35.4 万输入 token、24.6 万输出 token。
- v3 模型：在实验 7 的数据上加入 800 封改写样本（共 112,830 封），重新训练 TF-IDF 与 DistilBERT。DistilBERT v3 标准测试集 F1 0.9836、AUC 0.9995。
- 阈值均为各模型验证集上误报率 ≤ 1% 的阈值。

### 结果（钓鱼组为召回率，正常组为误报率；原始 → 改写后）

| 方法 | 英文钓鱼 (200) | 中文钓鱼 (19) | 英文正常 (99) | 中文正常 (20) |
|---|---|---|---|---|
| 系统判定（TF-IDF v2 校准 + 规则） | 0.985 → 0.980 | 0.895 → **0.895** | 0.000 → 0.000 | 0.050 → 0.000 |
| TF-IDF v2 | 0.985 → 0.980 | 0.895 → 0.789 | 0.000 → 0.000 | 0.050 → 0.000 |
| DistilBERT v2 | 1.000 → 1.000 | 0.526 → 0.579 | 0.010 → **0.212** | 0.000 → 0.000 |
| TF-IDF v3（+改写增强） | 0.980 → 0.980 | 0.895 → 0.789 | 0.000 → 0.000 | 0.000 → 0.000 |
| DistilBERT v3（+改写增强） | 0.990 → 0.990 | 0.737 → 0.737 | 0.010 → **0.071** | 0.000 → 0.000 |

### 结论

1. **英文钓鱼对改写基本免疫**：所有模型召回变化不超过 0.5 个百分点，钓鱼邮件的核心请求（验证账户、点击链接、转账）改写后依然存在。
2. **TF-IDF 在中文上有 2 封因改写而漏检**（召回 -10.5 个百分点）：改写把模板里的固定说法换成了同义表达，词频模型认不出。但**系统判定没有下降**，被漏掉的邮件由规则层（索取账号、紧迫感等）补回，体现了规则与模型融合的价值。
3. **DistilBERT v2 出现了新的"文风捷径"**：英文正常邮件被润色后误报率从 1% 升到 21%。原因是训练集里语句工整、措辞礼貌的邮件多是钓鱼和诈骗，模型把"写得像客服"当成了钓鱼特征——这正是大模型时代的风险：攻击者和正常用户都会用 AI 润色，文风不再能区分两者。
4. **改写增强有效但不彻底**：把 800 封改写样本（钓鱼和正常都有）加入训练后，DistilBERT 对润色正常邮件的误报从 21% 降到 7%，中文钓鱼召回从 53% 提高到 74%；TF-IDF 没有变化（改写带来的同义词太分散，800 封不足以覆盖）。
5. 对系统的决定：**系统继续使用 TF-IDF v2**。v3 没有带来可测的提升；DistilBERT v3 虽然改善明显，但英文改写误报 7% 仍高于要求，暂作为后续级联复核的候选。
6. 局限：中文组只有 19/20 封，单封邮件就是 5 个百分点；改写提示词是中性的，带有"规避检测"意图的对抗改写可能导致更大的下降，留作后续工作。
